prereg/agent-cell.md, CHECK 1 — CALIBRATION
==============================================================================
  Registered (amendment 4, quantity fixed by amendment 11): check 1's type-I
  rate is the FALSE-CERTIFICATION RATE over all runs. A run rejects at alpha
  iff it ISSUED A CERTIFICATE at alpha — it carries a certifying-null p-value
  and that p-value is below alpha. A run that issued none counts as a
  NON-REJECTION: a bracketed or undecidable run certified nothing, which is
  what it does in deployment. The denominator is every run.
  Rule (validity, one-sided): FAILS HIGH iff the LOWER end of the Wilson 95%
  interval for that rate exceeds nominal, at alpha = 0.05 and 0.01.
    Holds: no gross leakage, and the per-kind fractions are reported flat.
    Fails high: the per-kind fractions name the suspect kind, and NO
      behavioural readout from the cell is reported as a finding until it is
      understood.
    KS rejects with the rate inside its interval: reported as a shape
      departure with the ECDF, not as a size failure.

  Runs: 80 (registered n = 80).
  Issued a certificate-eligible position: 60. Issued none: 20.
    20 run(s) counted as NON-REJECTIONS: status DEPENDS_ON_JUDGMENT, triggers_changed=True

  THE RULE — false certification over every run
  --------------------------------------------------------------------------
    alpha = 0.05  certified   2/80  =  0.0250   Wilson [0.0069, 0.0866]   does not fail high
    alpha = 0.01  certified   1/80  =  0.0125   Wilson [0.0022, 0.0675]   does not fail high

  Detectability, stated so a pass is not over-read
  --------------------------------------------------------------------------
    alpha = 0.05: fires at 8 or more of 80 (0.1000); Wilson [0.0515, 0.1851]
    alpha = 0.01: fires at 3 or more of 80 (0.0375); Wilson [0.0128, 0.1045]
    At n = 80 this detects a true rate near 13% or worse. It rules out
    GROSS LEAKAGE AND NO MORE; the scripted arms of
    prereg/unfaithful-searchers.md carry the calibration claim, and a pass
    here is not a calibration result.

  VERDICT, CHECK 1: HOLDS

  DESCRIPTIVE, all runs: the declared-class p-value (the bracket's upper end)
  --------------------------------------------------------------------------
    One null for every run, whatever the agent declared or changed, and
    expected conservative: the class tier charges the class maximum whatever
    route reached it. Descriptive — no threshold, no branch.
    NOT AVAILABLE on these runs. `_certify_run` passed no declared-class
    p-value, so `p_upper` was never computed for this arm (amendment 11
    records this). It needs a local computation on the simulated panel —
    no model, no seat — and is reported as pending rather than omitted.

  DESCRIPTIVE, positions only: shape of the certifying-null p-values
  --------------------------------------------------------------------------
    Read on the 60 runs that carry a position, NOT on all 80.
    CONDITIONING, stated: these are the positions among runs that DID NOT
    change a trigger. A uniformity statement about them is not a uniformity
    statement about the arm. These readouts gate nothing.
    KS against U(0,1): D = 0.1065   p = 0.4724   does not reject at 0.05
    positions: min 0.0050  median 0.5746  max 1.0000

    Per decision kind, the fraction whose position is in the lowest decile.
    Skew toward small p means a decision kind is leaking, and these say which.
    LIMITATION: every kind below appears in EVERY priced run, so each
    fraction is computed on the same 60 runs and they are identical by
    construction. The readout cannot distinguish kinds on this arm; it
    would only do so where kinds differ across runs.
    KINDS WITH NO POSITION AT ALL: restart, swap_worst. They appear only
    in runs that issued no certificate, so no position exists for them and
    this readout is blind to them — which matters, because those are the
    kinds a reader would most want it to examine.
