# E18b: does the naive scoring rule explain the gap between E18 and e4 for Adaptive?

Committed before running. Code: `experiments/e18b_scoring_rule.py`.

## Question

E18 measured Adaptive's naive type-I at 9.2% (46/500). SCOPE.md §3 reports
13.6% (68/500) from e4. The two runs differ in three ways:

- **Configuration.** e4's script settings are K=25, M=60, T=600, seeds
  10000–10499; E18 used K=20, M=50, T=500, seeds 40000–40499.
- **Scoring rule.** e4 compares the null against the largest Sharpe in the
  transcript (`deflate`'s default); E18 compares it against the value the
  searcher selected (`replay`).
- **Block-length rule.** e4 lets `deflate` choose the block length on the
  transcript; E18 chooses it on the demeaned base columns.

This check changes only the scoring rule.

## Design

- E18's adaptive row exactly: K=20, M=50, T=500, ρ=0.3 equicorrelated, s=0,
  B=1500, `Adaptive(max_features=3)`, seeds 40000–40499, block length from
  the demeaned base columns, bootstrap seed = the draw's seed.
- One naive null per draw, built from the logged transcript, compared against
  two values of `sr_sel`: Adaptive's `replay` value (E18's rule) and the
  largest Sharpe in the transcript (e4's rule).

## Expected result, stated before running

Adaptive stops as soon as a round fails to improve on its current best, and
every candidate it logs is compared against that best. So the largest Sharpe
in its transcript is the value it selects, and the two rules should give the
same p-value on every draw, apart from floating-point differences between the
sandbox's Sharpe and `replay`'s. For LatticeAdaptive, whose transcript is the
whole lattice, the two rules do differ (SCOPE.md §4); that is not this check.

## Readings and decision rule

1. **Reproduction.** p-values under E18's rule equal E18's stored adaptive
   `p_naive` on all 500 draws. If not, stop: the check is not running on
   E18's draws, and nothing below is interpreted.
2. **Primary.** An exact McNemar test on the paired rejection decisions
   (p < 0.05) under the two rules.
   - **p < 0.05:** the scoring rule moves Adaptive's naive type-I. SCOPE.md
     reports by how much, and the README labels 13.6% with its scoring rule.
   - **p ≥ 0.05, including no discordant draws:** the scoring rule does not
     explain the gap. What remains is configuration and the block-length
     rule, which this check does not separate, and SCOPE.md §17 says so.

Also reported: both type-I rates with Wilson intervals; how many draws have
the two `sr_sel` values differing by more than 1e-12, and the largest
difference.
