# E16: does the P4 lemma's pointwise dominance explain e15's winner inflation?

Committed before running. Code: `experiments/e16_pointwise_dominance.py`.

## Question

The note's P4 lemma: under exchangeable features, for a two-step search that
anchors round 2 on the round-1 winner, the process null maximum `M_P` is at
least the realized-menu null maximum `M_C` on every bootstrap draw, so the
naive (realized-menu) p-value is at most the recursive (process) p-value draw
by draw. For a search that anchors on the round-1 loser, the inequality
reverses. e15 found winner anchoring inflates naive type-I (8.2%) and worst
anchoring does not (3.2%). Is P4 the mechanism, at finite T, in e15's
configuration?

## Design

- Searchers: `WinnerAnchor` and `WorstAnchor` (`searchers/dose_response.py`),
  `max_features=2`.
- Configuration (e15's): K=20, M=50, T=500, ρ=0.3 equicorrelated, s=0,
  sigma=1, B=1500.
- n=500 draws, seeds 20000–20499. Fresh block; paired across the two searchers.
- `sr_sel`: the searcher's own `replay` value on the real data.
- Common draws: one block length per draw, `select_block_length` on the
  demeaned base columns, passed to both the naive null
  (`estimator.bootstrap.null_max_bootstrap` on the logged transcript) and the
  recursive null (`estimator.recursive_bootstrap.recursive_null_max_bootstrap`
  on the base columns), both with bootstrap seed = the draw's seed. Replicate
  `b` then uses the same resampled time index in both nulls, so `M_P[b]` and
  `M_C[b]` are directly comparable.
- Recorded per draw: `p_naive`, `p_recursive`, `sr_sel`, winner, anchor, block
  length, and replicate counts of `M_P > M_C`, `M_P = M_C` (within 1e-9
  relative), `M_P < M_C`. The git commit is saved with the results.

## Predictions

- Winner: `p_naive ≤ p_recursive` in nearly every draw; `M_P ≥ M_C` in nearly
  every replicate.
- Worst: the reverse, `p_naive ≥ p_recursive` in nearly every draw.

## Decision rule

Primary statistic: the fraction of winner draws with `p_naive ≤ p_recursive`
(ties counted as satisfying it; the tie fraction reported separately).

- **≥ 0.90:** P4 is supported as the mechanism. Proceed to E17–E22.
- **< 0.80:** P4 is not the mechanism behind e15. Pause E17–E22 and rethink
  §4 of the note before spending compute.
- **0.80–0.90:** ambiguous. Report it and decide explicitly before running E17.

Secondary, reported but not gating: the worst-anchor fraction with
`p_naive ≥ p_recursive`; replicate-level dominance fractions for both
searchers; naive and recursive type-I at α=0.05 with Wilson intervals, as a
fresh-seed replication of e15's winner and worst rows.
